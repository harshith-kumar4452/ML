

## Definition

**Data preprocessing** is the process of cleaning, organizing, and transforming raw data into a suitable format so that a machine learning model can learn from it effectively.

Real-world data is rarely perfect. It may contain missing values, duplicate records, incorrect formats, outliers, or categories that a model cannot directly understand.

Data preprocessing helps address these issues before model training.

---

## 1. Why Do We Need Data Preprocessing?

Imagine building a machine learning model to predict students' marks.

| Student | Study Hours | Attendance (%) | Marks |
|---|---:|---:|---:|
| A | 2 | 80 | 45 |
| B | 4 | 90 | 65 |
| C | NaN | 85 | 70 |
| D | 8 | 110 | 90 |
| E | 4 | 90 | 65 |

This dataset has several issues:

- **Missing value:** Student C's study hours are missing.
- **Invalid value:** Student D's attendance is 110%, assuming attendance cannot exceed 100%.
- **Potential duplicate record:** Students B and E have identical values. Confirm whether they represent duplicate records before removing either.
- **Potential scaling issue:** Study hours and attendance have different numerical ranges.

Preprocessing helps investigate and handle these issues before training the model.

---

## 2. Major Data Preprocessing Techniques

### 2.1 Handling Missing Values

Fill missing values using methods such as:

- Mean imputation
- Median imputation
- Mode imputation
- Constant-value imputation
- K-Nearest Neighbors (KNN) imputation
- Deleting rows or columns when justified
- Adding a missing-value indicator when missingness may be informative

**Important:** Do not automatically replace missing values with zero. Zero may be a valid value, and the best method depends on the data and problem.

### 2.2 Handling Outliers and Invalid Data

Outliers are observations that differ substantially from most of the data. They may be genuine observations or data errors.

Common approaches include:

- Interquartile range (IQR) method
- Z-score method
- Box plots and distribution plots
- Capping or winsorization
- Log transformations
- Robust scaling
- Correcting invalid values using reliable source information

**Important:** An outlier is not automatically an error. Investigate before removing or changing it.

### 2.3 Feature Scaling

Feature scaling changes the numerical scales of features when the selected model benefits from it.

Common methods:

- **Standardization:** Centers values around the mean and scales by the standard deviation.
- **Min-max scaling:** Maps values to a specified range, often 0 to 1.
- **Robust scaling:** Uses statistics such as the median and interquartile range.

Scaling is often useful for KNN, K-means, SVM, PCA, and many gradient-based models. Tree-based models generally do not require standard scaling.

### 2.4 Categorical Encoding

Many machine learning algorithms require categorical data to be represented numerically.

Common methods:

- **One-hot encoding:** Creates separate indicator columns for categories such as `Red`, `Blue`, and `Green`.
- **Ordinal encoding:** Represents categories with a meaningful order, such as `Low`, `Medium`, and `High`.
- **Frequency encoding:** Represents a category using how frequently it appears.
- **Target encoding:** Represents categories using target-related statistics. This requires careful leakage prevention.

**Important:** Arbitrary integer labels can introduce a false order. Target encoding must be implemented carefully, often using out-of-fold calculations.

### 2.5 Data Splitting

Separate data into:

- **Training set:** Used to fit the model.
- **Validation set:** Used to compare models and tune settings.
- **Test set:** Used for final evaluation after decisions are complete.

Choose a split strategy appropriate to the task. Examples include stratified splitting for classification, chronological splitting for time-series data, and group-based splitting when records are related.

### 2.6 Other Preprocessing Techniques

- Removing confirmed duplicate records
- Correcting data types and inconsistent formats
- Handling inconsistent units
- Feature extraction
- Feature engineering
- Transforming skewed distributions
- Selecting or reducing features where appropriate

---

## 3. Typical Preprocessing Workflow

1. **Collect raw data.**
2. **Inspect the dataset:** Check its shape, data types, distributions, and target variable.
3. **Clean the data:** Investigate missing values, duplicates, invalid values, and inconsistencies.
4. **Split the data** into training, validation, and test sets using a suitable strategy.
5. **Fit preprocessing steps on training data only:** Learn imputation values, scaling parameters, and category mappings.
6. **Transform the data:** Apply the fitted transformations to training, validation, and test data.
7. **Train the model.**
8. **Evaluate performance** using a metric suitable for the problem.

### Preventing Data Leakage

**Core rule:** Split the data before fitting learned preprocessing steps.

For example, calculate the median used for imputation from the training set only. Then use that same median to transform validation and test data.

Fitting a scaler or imputer on the entire dataset before splitting allows information from the validation or test data to influence the training process. This can cause data leakage and produce overly optimistic results.

In scikit-learn, `Pipeline` and `ColumnTransformer` help keep preprocessing consistent and reduce the risk of leakage.

---

## 4. How Does Preprocessing Affect Model Performance?

Good preprocessing can:

- Improve data quality and consistency.
- Help algorithms learn useful patterns.
- Make numerical optimization more effective.
- Reduce errors caused by unsuitable data representations.
- Improve the reliability of model evaluation.

However, preprocessing does not automatically improve every model. For example, tree-based models generally do not need standard feature scaling, while KNN and SVM often benefit from it.

---

## 5. Simple Analogy

Think of machine learning as teaching a student:

- **Raw data** is the study material.
- **Data preprocessing** is organizing and correcting that material.
- **Model training** is the learning process.
- **Model evaluation** checks how well the student learned.

If the input data is misleading or poorly prepared, the model may learn the wrong patterns.

---

## 6. Key Takeaway

> **Data preprocessing is the process of cleaning and transforming raw data into a consistent, model-appropriate format before training, while avoiding information leakage.**

The goal is not to apply every available technique. It is to understand what problem each technique solves, when it is appropriate, and how to apply it correctly.
